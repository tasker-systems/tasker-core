# Rule register

Every rule in `doctrine/` has a row here, with its enforcement status in each consuming repo. This
file is what makes [tenet 1](tenets.md) checkable: a rule is either enforced by a named gate, or
says why it is not.

**Status vocabulary**

| Status | Meaning |
|---|---|
| **gated: `<gate>`** | A named CI check fails on a violation |
| **partial: …** | Enforced for part of the scope; what's missing is stated |
| **practiced** | The code follows it today, but nothing would catch a violation |
| **convention: …** | Deliberately not gated, with the reason |
| **uncovered** | Not followed, or not checked. A known hole |

<!-- consumers:begin -->

**Registered consumers.** This block and the consumer columns of every table below are
generated by [`tools/register.py`](../tools/register.py) from each consumer's
`.conventions/status.toml`; do not edit them by hand. Where a consumer and this file
disagree, the consumer wins: it is where the gate lives. A rule a generated column does
not list is **unexamined** there. For tasker-contrib the baseline covers its own surfaces
only; its templates and example apps are user-owned.

Every consumer column above is generated. temper's and tasker-core's were hand-taken until each
adopted (conventions#9, tasker-core#380); the hand-taken cells were replaced, not merged, because
each consumer's `status.toml` is a fresh reading of its own gates. At tasker-core's adoption, 135
of its 139 hand-taken cells disagreed, 69 changed verdict, and four claimed `gated` where its gates
do not enforce the rule (RUST-LINT-1, RUST-LINT-2, RUST-TYPE-1, TS-TOOL-1).
